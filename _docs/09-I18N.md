# BossZap — Internationalization (i18n)

## Supported Languages
| Code | Language | Role |
|---|---|---|
| `es` | Spanish | DEFAULT — all UI, landing, system defaults |
| `en` | English | Full translation |
| `pt-BR` | Brazilian Portuguese | Full translation |

## Library: next-intl
- Install: `npm install next-intl`
- Handles: routing, translations, date/number formatting, pluralization.

## Translation Files
```
src/messages/
├── es.json       (Spanish — source of truth)
├── en.json       (English — must have every key from es.json)
└── pt-BR.json    (Portuguese — must have every key from es.json)
```

## Rules (ALL MANDATORY)
1. NEVER hardcode user-facing text. Every string from translation files.
2. Spanish (es.json) is source of truth. Write it first, then translate.
3. Use `useTranslations('namespace')` in every component.
4. Format numbers/dates per locale using `useFormatter()`.
5. Language switcher: visible in navbar.
6. URL routing: `/es/dashboard`, `/en/dashboard`, `/pt-BR/dashboard`.
7. Default route (`/`) redirects to `/es/`.
8. Language preference stored in cookie + subscriber profile.
9. AI responds in subscriber's preferred_language.
10. PDFs use subscriber's preferred_language for all labels.
11. Emails sent in subscriber's preferred_language.
12. Admin dashboard language is independent from subscribers.
13. API errors return in language from Accept-Language header or user profile.
14. HSM templates must be approved per language (3 versions each).

## What to Translate
- All UI text, buttons, labels, headings, placeholders, tooltips, empty states.
- All validation messages.
- All toast/notification messages.
- All error messages.
- All email templates.
- All PDF labels and static text.
- Landing page content.
- AI onboarding messages.
- HSM templates (per language approval).
- Admin dashboard UI.

## What NOT to Translate
- Subscriber's own data (names, descriptions they typed).
- Technical identifiers, API keys, URLs.
- Brand names: BossZap, WhatsApp, Pix, Stripe.
